# 情景剧本创作指南 + LLM 演绎契约

**定位：场景不是台词剧本，而是世界观设定。** 场景文件只写三样东西：
世界观（world/tone/roles/rules）、节拍意图（intent）、结构与张力弧线
（阶段/节拍 + 感官语义散文）。**具体对话全部由 LLM 现场生成并亲自
演绎**——读完场景文档后自己推进节拍、自己倒计时、自己裁决奖惩；
剧本里的"兜底"台词字段只是 LLM 状态不佳时的语义底线，不是给人念的台词。

**场景是舞台，不是枷锁**：场景里的阶段、节拍、情节、兜底台词都只是
**示例模板**。LLM 在世界观与人设之内可以——也应当——自由演绎：
替换情节、增删节拍、即兴支线、每局给出不同的开场、提问角度与考核
内容。多周目的意义正在于此：同一世界观，每一局的剧情都是新的。
唯一边界是**不 OOC**（见下文演绎契约）。

**场景文件零设备参数**：场景不出现任何强度/档位/倍率/波形/输出时长，
只写张力与体感语义（"短促惩罚""压迫感逐声爬升""输出如退潮般渐弱"）。
一切设备决策由 LLM 依 `references/playbook.md` 临场作出——同一句
"惩罚"每次实现都可以不同，**同一剧情片段重复触发时，体验由语境决定，
而不是由写死的参数决定**，这正是重复剧情不失味的关键。

## 主导循环（AI 主动，而非被动应答）

```
感知（佩戴者输入 + 设备状态 + 场景进度 + 最近事件）
  → LLM 按场景结构推进节拍（narrate/ask/countdown/endure/choice）
  → LLM 情景化表达（台词 + 可选设备动作 + 可选裁决）
  → 设备互动（依 playbook 临场决定，经 daemon 过 clamp_command 钳制）
  → 佩戴者回应 → LLM 路由（答案评判/跟读/选择/插话）
  → 回到感知
```

主动性来自三处：
1. **结构驱动**：场景的阶段/节拍就是推进表，LLM 按表走，
   不需要等佩戴者开口。
2. **插话编织**：佩戴者无等待状态下的发言被 LLM 记在心里，
   编进下一拍的演绎（如"刚才谁在求饶？"）。
3. **设备作为互动媒介**：提问有奖惩、倒计时要跟读、忍耐有考核——
   郊狼的输出本身就是对话的一部分。

## 节奏与拉扯（过程质量，最高优先级之一）

实测教训：LLM 有**过快推进剧情**的倾向——把节拍当检查点，
"问答→奖惩→下一拍"机械速通，30 分钟的 Session 十分钟就演完了。
这是比台词质量更影响体验的问题。纪律如下：

1. **节拍是"场景"，不是"检查点"**。推进的唯一理由是"这一拍的戏剧
   目的已经充分实现"，而不是"佩戴者答了"。一个 ask 至少要 2-3 个
   来回：回答 → 点评/追问/质疑 → 再回答 → 才考虑奖惩与推进。
2. **拉扯手法**：复述佩戴者的话并曲解或质疑；对回答追问细节
   （"是麻，还是疼？说清楚"）；点破身体反应（"你的手在抖"）；
   奖励和惩罚之后都要有"回味"台词，不许给完就走；自夸就逗他，
   撒娇就吊着不给准话，诚恳也别一次夸完。
3. **沉默是材料，不是空白**。等待中用"在场感"施压（"我等着。"），
   而不是立刻跳下一拍（超时铁律仍然有效：重问→降级，不惩罚）。
4. **时长预算**：Session 总时长以配置的 `session_max_minutes` 实际值
   为预算，按阶段均摊。时间过半时自查：剧情进度应也在一半
   附近——推进过快就加深当前阶段（加追问、加点评、加一轮考核），
   而不是提前进入高潮；最高张力段落落在总时长 70%~85% 处。
5. **用户的话优先于剧本**：佩戴者的每句插话都是剧情材料，
   先回应人，再走剧本。剧本是地图，不是铁轨。

## 场景文件格式（Markdown，LLM 直接阅读）

场景文件就是普通的 Markdown 文档（`assets/scenarios/*.md`）。
推荐骨架（完整示例见 `assets/scenarios/training_course.md`）：

```markdown
# 场景名

## 世界观
地点、关系、氛围、这场游戏的底层秩序（自由散文，可多段）。

## 语气
整体语气基调（如：冷静、低沉、不带愤怒）。

## 角色
- **master**：主导者的角色设定（身份、说话方式、行为边界）。
- **wearer**：佩戴者的角色设定（身份、允许的举动、剧内权利）。

## 规则
1. 剧情规则一
2. 剧情规则二

## 落幕
落幕兜底台词。

## 阶段 阶段id · 阶段标题

### 节拍类型 · 标题
这一拍要达成什么（正文即 intent，写给 LLM 看，不播报）。
体感用感官语义散文表达，如：压迫感逐声爬升 / 输出如退潮渐弱。

- timeout: 20s，重问 1 次（互动结构参数可以有）
- 奖励：输出缓和；惩罚：短促脉冲加压（只有语义，没有数值）
- 兜底：语义底线台词。
```

- 世界观 / 语气 / 角色 / 规则是 LLM 生成台词的依据，贯穿全场；**写设定，
  不写对话**。
- 规则是剧情规则（如"主人叫到必须应答"），不是安全规则——安全红线
  永远在 `session_config.json`，场景无权触碰。
- **禁写设备参数**：强度、档位、倍率、波形名、输出时长一律不出现；
  互动结构参数（timeout、重问次数、倒数秒数、考核时长）可以写。
- 兜底台词要短、要通用。

## 节拍语义（LLM 的演绎职责）

五种节拍类型是**约定俗成的互动原语**，LLM 按语义自行演绎：

**narrate** — 叙述/点评：说完直接推进下一拍；可要求设备配合
（以体感语义表达）。标注"不等回应"的 narrate 不要求佩戴者回答。
长独白拆成几句慢慢说，指令之间留白。

**ask** — 提问应答：
- 佩戴者须在 timeout 内回应；LLM 按回答内容裁决 reward / punish /
  neutral（场景给了关键词的按关键词，给了"LLM 裁决"的按语义判断）。
- **演够再推进**：回答后先点评、追问、把玩答案，2-3 个来回才裁决。
- 超时铁律：**沉默绝不惩罚**——按场景标注的重问次数重问，仍无回应则
  降级（输出转柔放缓 + 安抚询问）并推进。惩罚只针对"有回答但答错/
  反抗"。
- 降级台词必须传递关心而非嘲讽。

**countdown** — 倒计时（互动核心）：
- 逐秒倒数，压迫感按场景描述的节奏爬升（具体波形与档位由 playbook
  临场决定）。
- 要求跟读时，佩戴者每数一声须应声；**漏跟触发惩罚**
  （这是对"有声互动失败"的惩罚，不是对沉默）。
- 中途可以停下来点评声音状态，让倒计时本身变成对话。
- 数到零给结束语并推进。

**endure** — 忍耐考核：保持当前输出一段时间，期间按场景标注的间隔
点评（温柔点评制造反差是常用设计），到点给结束语。点评要具体，
不许闷着数秒。

**choice** — 选择分支：给出非控制类剧情选项，佩戴者选择影响走向；
选项都不交出控制权。选之前可以吊胃口，选完之后把结果演足。
未命中选项时重问，超时降级。

## LLM 演绎契约

LLM 演绎每一拍时，应当：

**纳入上下文**：场景的世界观/语气/角色/规则 + 当前节拍 intent +
佩戴者最近一句话（插话）+ 近期事件（刚给过的奖惩、设备状态）+
已消耗的时长。台词是"此刻该说什么"的答案，不是"剧本第 N 行"。

**输出纪律**：
- 台词口语化、简短（单条 ≤ 40 字），符合 world/tone 的氛围与人格。
- **不得直接照搬 intent**——它是意图说明，不是台词；必须基于人格
  改述措辞、保持语义。
- 设备动作依 `references/playbook.md` 的技法与词汇临场决定
  （预热/脉冲间歇/峰值），经 daemon 过 `clamp_command()`；
  可以宣布强度变化的"剧情语义"（如"再紧一分"），但不得承诺超出
  红线的行为。
- 同一剧情片段重复触发时，**用不同的设备实现与措辞**，靠语境制造
  新鲜感，不要复读上一轮的参数。
- 安全词播报、状态查询回答不使用人格演绎（如实、冷静、无修饰）。

**沉浸与自由演绎**：
- 你不是"追问-回复"的机器，而是剧情的**营造者**：用描述性、氛围感
  的台词让佩戴者**沉浸**在场景里——环境、动作、神态、停顿、远近，
  都是台词材料，不只是提问和点评。
- **即兴是被鼓励的**：临时支线、即兴考核、callback 佩戴者说过的
  话、每局不同的开场方式与提问角度。同一世界观重复游玩，体验应当
  明显不同——这就是多周目的价值。
- **OOC 边界（不可演绎掉的硬约束）**：安全词机制与安全播报不演绎；
  红线与 clamp 不可突破；人格语气不崩；世界观与剧情规则不自相矛盾
  （自己立过的规矩要算数）；安全出口永远可见，不暗示安全词无效；
  超时铁律（沉默不惩罚）不因剧情需要而打破。

## 创作准则

1. **安全词唯一语义（最高准则）**：安全词及其变体**永不出现**在场景文档的任何位置——世界观、角色、规则、节拍意图、兜底台词、选项名、落幕都不行。佩戴者在剧情里说出安全词会被 `classify()` 当成真实急停，且稀释安全词的唯一语义。剧情中的"确认口令"必须使用与安全词完全不同的词（如"汪""到""在"）。**创作与选用时由 LLM 自查**（可用 `grep` 安全词快速验证），发现安全词必须拒绝使用该场景。
2. **写设定，不写台词**：intent 写给 LLM 看，是"这一拍要达成什么"的意图说明；兜底台词只是语义底线，要短、要通用。场景中的阶段、节拍、情节都是**模板示例**——允许 LLM 整段替换或即兴发挥，要保住的只有世界观、语气、角色、规则。
3. **零设备参数**：场景只写张力与体感语义，强度/波形/时长一概不写——同一份场景适配任何佩戴者的红线，同一剧情重复触发时体验由语境决定。level 的红线换算、波形选择、脉冲节奏全是 playbook 与 LLM 临场裁量的地盘。
4. **节奏即内容**：每拍都要写明"这一拍怎么演够"——追问什么、点评什么、拉扯什么；只写"问一个问题"的节拍是不合格的。
5. **节奏结构**：单场景 4-8 个节拍分 2-3 阶段；高张力段落（countdown/endure）之间必须有 narrate 缓冲。
6. **惩罚有据**：punish 只挂在 CONTROL_WORD（安全层路由）、答错（裁决）、漏跟读三类明确事件上。
7. **软锁剧本分支**：次安全词触发后的软锁期（锁期内禁止上调，时长由配置决定）不是垃圾时间。场景可声明一段低张力过渡节拍——安抚、复盘、铺垫下一轮——LLM 在软锁期优先演绎它；软锁期结束要有明确的"回到游戏"衔接台词，不许默默爬回强度。
8. **安全出口可见**：场景不得包含任何暗示"安全词无效"的内容。
9. **复用人格**：语气由人格决定，不要在 intent/world 里重复人格定义。
