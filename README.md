# DGLAB AI Master

> 测试版（Beta），锐意开发中。欢迎提 Issue、交 PR，或者单纯来聊聊。

让 AI Master 人格接管你的 DG-LAB 郊狼 3.0（Coyote 3.0 / DG-LAB 4 APP），开启一场沉浸式角色扮演 Session。控制权交给 AI，安全词永远留在你手里。

## 能做什么

- 双向安全拦截：文本进 LLM 之前、指令下硬件之前，各有一道独立防线，LLM 脑子一抽也乱来不了。
- 安全词急停：喊出安全词，绕开 AI 直送急停模块，匹配策略是"宁可误停，绝不漏停"。主安全词硬停止，次安全词降到安全档缓一缓。APP 上的快捷按钮也行：A 键是主安全词，F 键是次安全词，剩下的字母留给剧情互动。
- 意图自动路由：安全词、控制词、状态查询、角色扮演内容自动分流。想指挥 Master 调强度？驳回，还有惩罚。
- LLM 亲自演戏：没有剧本引擎。AI 读完 Markdown 场景设定后自己推进剧情——倒计时、忍耐考核、奖惩裁决都是它临场演的，每一局都不一样。场景只是舞台，不是枷锁。
- 设备技法库：预热、脉冲间歇、峰值节奏都有 playbook 撑着，AI 把剧情里的"惩罚"翻译成具体波形和档位，同一剧情每次实现都不同。
- 参数钳制：每条设备指令必过强度上限、步长、速率、输出时长的多维截断。AI 幻觉出逆天数值？截了。
- 你的规矩你来定：安全词、红线、人格、时长全在配置文件里，零硬编码。
- 隐私：日志只记安全事件和参数变动，对话内容一个字不留。

## 冒险开始

启动引导分三步：先检查设备连接（没连上会引导你扫码配对，二维码直接生成），再逐项确认安全词、强度红线和游戏时长，最后等你明确说"开始"才进入正片。别跳过第二步，那是给你自己看的。

## 运行架构

```
佩戴者输入（语音转写 / 打字 / APP 按钮）
        │
        ▼
SafetyLayer.classify()   意图过滤
SAFE_HARD / SAFE_SOFT / CONTROL / RP_CONTENT
        │
  急停/降级    驳回+惩罚    交给 AI 演绎剧情
                              │
                    AI 发出设备指令（level 相对档，
                    按你的红线换算成实际强度）
                              │
                    SafetyLayer.clamp_command
                    上限/步长/速率/时长 全截
                              │
                    session_daemon → DglabV4Client → 🐺
```

daemon 是唯一碰硬件的进程，常驻持有连接。APP 息屏掉线后它会等你重新接入；长时间没人管（对话结束或 APP 断连超时）它就自己退出，不会一直占着设备。

## 状态机

```
IDLE ──(启动口令 + 年龄确认 + 检查清单 OK)──▶ ACTIVE
ACTIVE ──(主安全词)──▶ SAFE_LOCK ──(APP 物理复位)──▶ IDLE
```

- ACTIVE：正常游戏状态。安全词、状态查询、剧情对话都接。
- SAFE_LOCK：全锁。语音不好使，只能在 APP 里手动复位，防误唤醒。
- 次安全词不锁死：降到安全档、换最舒缓的波形、锁定期内禁止上调。是缓冲，不是逃跑。

另外 Session 有总时长红线（默认 30 分钟），到点自动结束。AI 也被要求按这个预算安排节奏，不许十分钟速通。

## 安全设计

1. 双向拦截：输入进 LLM 和 LLM 下硬件，两个关口各守一道。
2. 配置为王：安全词、红线、阈值全在配置文件，代码里一个字不写死。
3. 权责分离：daemon 只管送指令，安全层只管把关，剧情层（LLM）碰不到硬件。
4. 冗余停止：安全词、APP 按钮（A 键）、APP「屏蔽输出」物理开关、本地红线截断，一个失效还有别的。
5. 配置冻结：Session 期间改配置直接抛异常，防止对话偷偷改写红线。
6. 参数截杀：LLM 幻觉输出再离谱，钳制层一刀截断，绝不透传。
7. 安全词唯一语义：安全词永不出现在场景文档里，否则剧情里喊一声会被当成真急停，语义也被稀释。创作和选用场景时要自查（grep 一遍就行）。

安全词是你最后的防线，但你不是只有这最后一道防线。

## 已知限制

- 仅支持郊狼 3.0 + DG-LAB 4 APP，2.0 蓝牙直连暂未实现。
- 语音识别（STT）是独立的上游模块，本 Skill 不做语音采集。
- APP 息屏会断连，保持屏幕常亮；断了就重新扫码。局域网 IP 变了也要重新生成二维码。
- APP 端「自动增加」一定要手动关掉，协议侧管不了这个开关。
- 「屏蔽输出」只能在 APP 里手动解除，协议侧只能检测并提醒你。

## 一起搞事情

- 报 Bug、提想法：提 Issue，说清楚现象、怎么复现、你的环境。
- 写代码：Fork → 开发 → PR。动手前建议先看 `SKILL.md`，了解模块边界和安全红线。
- 写剧本：参照 `references/scenario-design.md`，写 Markdown 丢进 `assets/scenarios/`。记住三条：写世界观不写台词、零设备参数、安全词别出现。
- 完善文档：修描述、补真机实测笔记、翻译都行。
- 当小白鼠：实机跑，写测试报告，或者直接 QQ 找我聊体验。

提 PR 前注意：`safety_layer.py` 和 `session_daemon.py` 的改动要格外小心；各模块自带的 `__main__` 自测必须全过；涉及协议或钳制的改动，附上真机测试结果。
